0 What you'll build · 무엇을 빌드하나요

You'll produce two command-line programs from Temporal's source code: temporal-server-debug (the Temporal server, built in debug mode with relaxed internal timeouts) and tdbg (a tool that decodes the raw data in the database). You'll also start the databases it needs with Docker.

Temporal 소스 코드로부터 두 개의 명령줄 프로그램을 만듭니다: temporal-server-debug(내부 타임아웃이 완화된 디버그 모드 Temporal 서버)와 tdbg(데이터베이스의 원시 데이터를 해독하는 도구)입니다. 그리고 서버가 필요로 하는 데이터베이스를 Docker로 실행합니다.

You will NOT write any Go / Go 코드를 작성하지 않습니다

make runs the build recipes for you and Go compiles the code automatically. You only need Go installed so the compiler is available.

make가 빌드 과정을 대신 실행하고 Go가 코드를 자동으로 컴파일합니다. 컴파일러를 쓸 수 있도록 Go를 설치만 하면 됩니다.

1 System requirements · 시스템 요구사항

The database stack (MySQL, Elasticsearch, Cassandra, and more) runs in Docker and is memory-hungry. Have ≥ 8 GB RAM free (allocate ≥ 6–8 GB to Docker Desktop), ~ 15 GB free disk, and a stable internet connection (the first build downloads several hundred MB of Go packages and Docker images).

데이터베이스 스택(MySQL, Elasticsearch, Cassandra 등)은 Docker에서 실행되며 메모리를 많이 사용합니다. 여유 RAM 8GB 이상(Docker Desktop에 6~8GB 이상 할당), 여유 디스크 약 15GB, 그리고 안정적인 인터넷 연결이 필요합니다(첫 빌드에서 수백 MB의 Go 패키지와 Docker 이미지를 내려받습니다).

2 Install the tools · 도구 설치

Pick your operating system with the OS switch above (on paper, both are shown). You need four tools: Git, Go 1.26.4+, GNU Make, and Docker. The Temporal CLI is a handy extra.

위의 OS 스위치로 운영체제를 선택하세요(인쇄본에는 둘 다 표시됩니다). 네 가지 도구가 필요합니다: Git, Go 1.26.4 이상, GNU Make, Docker. Temporal CLI도 있으면 편리합니다.

macOS

The easiest path is Homebrew. If you don't have it, install it first, then install the tools. xcode-select --install provides Git and Make; Homebrew provides Go.

가장 쉬운 방법은 Homebrew입니다. 없다면 먼저 설치한 뒤 도구들을 설치하세요. xcode-select --install이 Git과 Make를 제공하고, Homebrew가 Go를 제공합니다.

# 1) Xcode Command Line Tools (gives you git + make)
xcode-select --install

# 2) Homebrew (skip if already installed)
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"

# 3) Go, and (optional) the Temporal CLI + a newer GNU Make
brew install go temporal make

# 4) Docker Desktop — download & install, then LAUNCH it once
#    https://www.docker.com/products/docker-desktop/  (Apple Silicon & Intel)
Apple Silicon note

Everything runs natively on M-series chips. In Docker Desktop, keep "Use Rosetta for x86/amd64 emulation" enabled (Settings → General) for the widest image compatibility.

M 시리즈 칩에서 네이티브로 동작합니다. 이미지 호환성을 위해 Docker Desktop 설정(Settings → General)에서 "Use Rosetta for x86/amd64 emulation"을 켜 두세요.

Windows → first install WSL2 / Windows는 먼저 WSL2 설치

Windows users start here / Windows 사용자 먼저

Temporal is built inside Linux. On Windows, install WSL2 + Ubuntu, then do everything else inside the Ubuntu terminal. Open PowerShell as Administrator, run the command below, reboot, then open "Ubuntu" from the Start menu.

Temporal은 Linux 환경에서 빌드합니다. Windows에서는 WSL2 + Ubuntu를 설치한 뒤 나머지 모든 작업을 Ubuntu 터미널에서 진행하세요. PowerShell을 관리자 권한으로 열어 아래 명령을 실행하고, 재부팅한 다음 시작 메뉴에서 "Ubuntu"를 여세요.

# Windows PowerShell (Administrator) — installs WSL2 + Ubuntu
wsl --install
# reboot, then open "Ubuntu" and continue with the commands below

Ubuntu / WSL2 / Linux — Git, Make, Go

Ubuntu's packaged Go is usually too old, so install Go from the official download. (For ARM machines, replace amd64 with arm64.)

Ubuntu 패키지의 Go는 대개 너무 오래되었으므로 공식 배포판으로 설치합니다. (ARM 머신은 amd64를 arm64로 바꾸세요.)

# 1) Git + GNU Make
sudo apt update && sudo apt install -y git make curl

# 2) Go 1.26.4 (official) — remove any old Go, then install to /usr/local
curl -LO https://go.dev/dl/go1.26.4.linux-amd64.tar.gz
sudo rm -rf /usr/local/go && sudo tar -C /usr/local -xzf go1.26.4.linux-amd64.tar.gz

# 3) Put Go on your PATH (add this line to ~/.profile, then re-open the shell)
export PATH=$PATH:/usr/local/go/bin

# 4) (optional) Temporal CLI
curl -sSf https://temporal.download/cli.sh | sh

Docker

Windows (WSL2): install Docker Desktop for Windows, then enable Settings → Resources → WSL Integration for your Ubuntu distro. Native Linux: install Docker Engine and add yourself to the docker group.

Windows(WSL2): Docker Desktop for Windows를 설치하고 Settings → Resources → WSL Integration에서 Ubuntu 배포판을 켜세요. 네이티브 Linux: Docker Engine을 설치하고 본인 계정을 docker 그룹에 추가하세요.

# Native Linux only (skip on Windows/WSL2 — Docker Desktop handles it)
curl -fsSL https://get.docker.com | sh
sudo usermod -aG docker $USER      # then log out and back in
✔ Verify / 확인 — run these; each should print a version: 
git --version
go version            # installed Go; the build auto-fetches 1.26.4 if needed
make --version
docker --version
docker compose version
Go version / Go 버전

If go version shows something older than 1.26.4, that's usually fine — modern Go automatically downloads the exact toolchain the project pins (go 1.26.4 in go.mod) on the first build.

go version이 1.26.4보다 낮게 나와도 보통 괜찮습니다 — 최신 Go는 첫 빌드 때 프로젝트가 지정한 정확한 툴체인(go.mod의 go 1.26.4)을 자동으로 내려받습니다.

3 Get the source code · 소스 코드 받기

Clone the Temporal server repository and move into it. All later commands run from this folder. On WSL2, clone inside the Linux home (~), not /mnt/c — it's far faster.

Temporal 서버 저장소를 클론하고 그 폴더로 이동합니다. 이후 모든 명령은 이 폴더에서 실행합니다. WSL2에서는 /mnt/c가 아니라 Linux 홈(~) 안에 클론하세요 — 훨씬 빠릅니다.

git clone https://github.com/temporalio/temporal.git
cd temporal

4 Apply the workshop patch · 워크숍 패치 적용

Workshop-specific / 워크숍 전용

This one-line source change raises the workflow-task timeout cap from 120 s to 15 min, so you can hold a debugger breakpoint inside workflow code for up to 15 minutes. Skip it only if you want a plain debug build.

이 한 줄짜리 소스 변경은 워크플로 태스크 타임아웃 상한을 120초에서 15분으로 올려, 워크플로 코드 안에서 디버거 중단점을 최대 15분까지 유지할 수 있게 합니다. 일반 디버그 빌드만 원하면 건너뛰어도 됩니다.

# macOS (BSD sed):
sed -i '' 's/maxWorkflowTaskStartToCloseTimeout = 120 \* time.Second/maxWorkflowTaskStartToCloseTimeout = 15 * time.Minute/' \
  service/history/api/create_workflow_util.go

# Linux / WSL2 (GNU sed):
sed -i 's/maxWorkflowTaskStartToCloseTimeout = 120 \* time.Second/maxWorkflowTaskStartToCloseTimeout = 15 * time.Minute/' \
  service/history/api/create_workflow_util.go

# verify the change:
grep maxWorkflowTaskStartToCloseTimeout service/history/api/create_workflow_util.go
# expected -> maxWorkflowTaskStartToCloseTimeout = 15 * time.Minute

5 Build the binaries · 바이너리 빌드

Build the debug server, tdbg, and the schema tool. The first build is slow (it downloads all Go packages and may fetch the Go 1.26.4 toolchain) — several minutes is normal. Later builds are fast.

디버그 서버, tdbg, 스키마 도구를 빌드합니다. 첫 빌드는 느립니다(모든 Go 패키지를 내려받고 Go 1.26.4 툴체인을 가져올 수 있음) — 몇 분 걸리는 것이 정상입니다. 이후 빌드는 빠릅니다.

make temporal-server-debug     # -> ./temporal-server-debug
make tdbg                       # -> ./tdbg
make temporal-sql-tool           # -> ./temporal-sql-tool (installs the DB schema)
✔ Verify / 확인 
ls -la temporal-server-debug tdbg temporal-sql-tool   # three files exist
./tdbg --help | head

6 Start the databases · 데이터베이스 실행 Terminal 1

This starts MySQL, the Temporal Web UI, and other services with Docker Compose. It keeps running — leave this terminal open and open a new one for the next steps. Make sure Docker Desktop is running first.

Docker Compose로 MySQL, Temporal 웹 UI 등을 실행합니다. 계속 실행 상태로 유지되므로 이 터미널은 열어 두고 다음 단계는 새 터미널에서 진행하세요. 먼저 Docker Desktop이 실행 중인지 확인하세요.

make start-dependencies         # MySQL :3306, Temporal UI :8080, Grafana, ...
# wait until the log settles (MySQL "ready for connections")

7 Install the schema · 스키마 설치 Terminal 2

Create the Temporal tables inside the freshly-started MySQL. Run this once (re-run any time you want a clean database).

방금 실행한 MySQL 안에 Temporal 테이블을 생성합니다. 한 번만 실행하면 됩니다(데이터베이스를 초기화하고 싶을 때마다 다시 실행).

cd temporal
make install-schema-mysql        # creates the `temporal` + `temporal_visibility` DBs

8 Run the debug server · 디버그 서버 실행 Terminal 3

Start the server you built, pointed at MySQL. It keeps running — leave it open.

빌드한 서버를 MySQL을 향하도록 실행합니다. 계속 실행되므로 열어 두세요.

./temporal-server-debug \
  --config-file config/development-mysql8.yaml \
  --allow-no-auth start
# gRPC on :7233 · Web UI on http://localhost:8080

9 Verify everything works · 정상 동작 확인 Terminal 4

Create the default namespace, open the Web UI, and confirm tdbg can talk to the server.

기본 네임스페이스를 만들고, 웹 UI를 열고, tdbg가 서버와 통신하는지 확인합니다.

temporal operator namespace create --namespace default
# open the dashboard:  http://localhost:8080
./tdbg --address 127.0.0.1:7233 cluster describe   # should print cluster info
Done / 완료

If the namespace is created, the UI loads, and tdbg responds, your environment is ready for the workshop. 🎉

네임스페이스가 생성되고 UI가 열리며 tdbg가 응답하면, 워크숍을 위한 환경이 준비된 것입니다. 🎉

10 Troubleshooting · 문제 해결

Symptom / 증상Fix / 해결
make: command not foundEN: Make isn't installed — see step 2. / KO: Make가 설치되지 않았습니다 — 2단계 참고.
Cannot connect to the Docker daemonEN: Start Docker Desktop (or sudo systemctl start docker on Linux). / KO: Docker Desktop을 실행하세요(Linux는 sudo systemctl start docker).
Build fails on Go version / Go 버전 오류EN: Ensure internet so Go can fetch the 1.26.4 toolchain; go version ≥ 1.21. / KO: 인터넷 연결 확인, go version 1.21 이상.
port ... already in use (7233/8080/3306)EN: Another Temporal/DB is running — stop it. / KO: 다른 Temporal/DB가 실행 중입니다 — 종료하세요.
WSL2 build extremely slow / WSL2 빌드가 매우 느림EN: Clone under the Linux home ~, never /mnt/c/.... / KO: /mnt/c/...가 아니라 Linux 홈 ~에 클론하세요.
Docker runs out of memory / Docker 메모리 부족EN: Raise Docker Desktop memory to ≥ 8 GB (Settings → Resources). / KO: Docker 메모리를 8GB 이상으로 올리세요.
temporal: command not foundEN: Temporal CLI is optional — install it (step 2) or use the Web UI. / KO: Temporal CLI는 선택 사항입니다 — 설치하거나 웹 UI를 쓰세요.

Teardown / 정리

Press Ctrl+C in the server terminal, then stop the Docker services:

서버 터미널에서 Ctrl+C를 누른 뒤 Docker 서비스를 종료하세요:

make stop-dependencies

Reference: the Temporal repo's CONTRIBUTING.md and Makefile. Go 1.26.4, no C compiler required (CGO_ENABLED=0). 참고: Temporal 저장소의 CONTRIBUTING.md와 Makefile. Go 1.26.4, C 컴파일러 불필요(CGO_ENABLED=0).
